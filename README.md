# 白皮批量制作助手 v1.0

一个运行在 **WPS 文字** 中的 JS 加载项：读取 Excel 数据表，按 Word / Excel 白皮模板批量生成封面文件，并尽量保持模板原有的横线、字体、字号与上下对齐关系。

> 本仓库为公开发布版本（v1.0），已移除早期版本中的“小惊喜”入口与收款二维码图片，并清理了未使用的演示文件。项目以 [MIT License](LICENSE) 开源。

---

## 功能特性

- **批量生成**：一行 Excel 数据生成一份白皮文件，输出文件名默认取“书名”。
- **模板自适应**：同时支持 Word 模板（`.doc` / `.docx`）和 Excel 模板（`.xlsx`），按模板中实际存在的字段生成，不强制固定字段组合。
- **字段别名与空格兼容**：兼容标签前导空格、汉字之间的空格、中英文冒号，以及常见字段别名（如“编号/序号”“类型/种类”）。
- **横线保真**：模板中的编号横线按原字符范围处理；原本为空的横线逐字符保持原样，不重建、不改变长度和起止位置。
- **序号不写入成品**：`序号`、`编号` 只用于识别数据行和生成文件名，成品中的编号会被清空，并保持横线长度不变。
- **字体规则**：模板横线上原本没有文字时，填入值使用黑体三号（16 磅）；模板已有文字时保留原有字体字号，并在分析模板时提示不符合黑体三号的字段。
- **中心对齐校验**：按模板中“种类”等字段的文字中心，对同类字段做上下中心与横线长度校准（可在界面关闭）。
- **生成前拦截**：数据表缺少模板必需字段时阻止生成，避免产出内容不完整的白皮。
- **保存后校验**：可选项，保存后重新打开文件，核对字段值与格式是否落盘。
- **本地处理**：不联网、不上传、无遥测，文档只在本机读写（见[安全与隐私](#安全与隐私)）。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（x64 或 x86） |
| 办公软件 | WPS Office（需支持 JS 加载项，建议使用较新版本） |
| Node.js | 仅一键启动脚本与开发调试需要，建议 Node.js 18 LTS 及以上 |
| 字体 | 模板使用的字体需已安装在本机（如黑体、仿宋、方正字体等） |

> 插件本体是静态 HTML/JS，不依赖构建即可运行；Node.js 只用于 `wpsjs debug` 启动调试服务和安装开发依赖。

## 快速开始

### 方式一：一键启动（推荐）

1. 安装 [Node.js LTS](https://nodejs.org/)（安装时保留“添加到 PATH”）。
2. 双击项目根目录的 **`启动.bat`**。
3. 脚本会依次检查 Node.js、npm、`wpsjs`，缺少时自动安装；首次运行缺少 `node_modules` 时会自动执行 `npm install`。
4. 随后执行 `wpsjs debug` 启动调试服务并拉起 WPS。
5. WPS 中出现 **「白皮制作」** 选项卡后，点击 **「批量制作白皮」** 打开右侧任务窗格。

> 启动脚本运行期间请不要关闭黑色命令行窗口；关闭窗口后调试服务会停止。

### 方式二：手动启动

已安装 Node.js 与 `wpsjs` 时，在项目目录执行：

```bat
npm install
wpsjs debug
```

> `npm run dev` 只会启动 Vite 静态服务器用于单独预览任务窗格页面，不会把加载项注册到 WPS；正常调试请使用 `wpsjs debug`。

### 方式三：在 WPS 中添加加载项

在 WPS 中打开「开发工具 → 加载项 → 添加」，选择本项目的 `index.html`（或按所用 WPS 版本的 JS 加载项说明注册 `manifest.xml`）。

## 使用步骤

1. 点击 **「批量制作白皮」** 打开任务窗格。
2. 选择 **Excel 数据文件**（`.xlsx` / `.xls`）。
3. 选择 **白皮模板文件**（`.doc` / `.docx` / `.xlsx`）。
4. 选择 **输出文件夹**。
5. 确认界面显示 **「模板匹配：已通过」**，并核对字段映射。
6. 点击 **「预览第一份」** 检查效果，确认无误后点击 **「批量生成」**。
7. 生成结束后可在结果区查看成功/失败数量与错误日志，或点击 **「打开输出文件夹」**。

生成过程中可点击 **「取消任务」** 停止后续文件。

## 生成规则

- **数据工作表识别**：优先使用名为 `06白皮制作单` 的工作表；否则按表头结构选择包含“书名/教辅名称”或“序号”，且至少包含一个可填写字段的工作表。不会再用低相似度规则误选无关工作表。
- **字段来源**：以模板实际识别到的字段为准，从 Excel 表头按别名匹配取值；`使用年级及册次` 与拆分后的 `使用年级` + `册次` 互相兼容。
- **日期规范化**：Excel 日期统一按 `yyyy-mm-dd` 读取，再按模板格式写入，避免区域设置导致日期错位。
- **编号处理**：成品中的编号字段一律清空；若模板编号处原本有示例数字，只把数字替换为等长空白，横线不缩短、不延长。
- **空横线默认字体**：模板横线上没有原文字时，填入值统一为黑体、三号（16 磅）。
- **文件名**：默认使用书名；非法字符会被替换，超长名称会截断；开启“禁止覆盖已有文件”时自动追加序号，避免覆盖。
- **校验**：默认开启“严格保持模板格式”“自动进行上下中心线校验”“保存后重新打开校验”“禁止覆盖已有文件”，均可在界面中关闭。

## 安全与隐私

本项目在公开发布前做了一次源码审计，结论如下：

- **不联网**：运行时代码中没有任何 `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` 调用，不访问远程地址，不上传文档或数据。`启动.bat` 首次运行时通过 npm 安装 `wpsjs` 与项目依赖，这一步需要联网；加载项本身运行期间不发起网络请求。
- **无遥测**：不收集账号、机器信息或使用统计；日志仅保存在任务窗格内存中，关闭窗格即释放。
- **无动态代码执行**：没有 `eval`、`new Function`、远程脚本加载或混淆载荷。
- **无系统命令执行**：运行时代码不使用 `ActiveXObject`、`WScript.Shell`、`Shell.Application` 或 `child_process`；仅通过 WPS 提供的 `wps.OAAssist.ShellExecute("explorer.exe", ...)` 打开用户选择的输出目录或预览文件。
- **文件访问最小化**：
  - Excel 数据文件通过浏览器 `FileReader` 读取，仅限用户在选择框中显式选择的文件；
  - 模板读取、复制与成品写入通过 WPS 自带的 `Application.FileSystem` 完成，只作用于用户选择的模板和输出目录；
  - 输出文件名经过非法字符清理，不会跳出所选输出目录。
- **无硬编码凭据**：仓库中不含令牌、密钥、账号或个人信息；回归测试已去除内部样例文件名与真实人名/机构名。
- **页面输出转义**：字段映射、错误日志和结果列表在写入 `innerHTML` 前均经过 HTML 转义，避免 Excel 内容破坏页面结构。

> 提示：WPS 加载项以当前用户权限运行。请只从可信来源获取并安装加载项；`启动.bat` 首次运行会通过 npm 安装 `wpsjs` 与项目依赖，这一步需要联网。

## 已知限制

- 仅支持 Windows 与 WPS Office；Microsoft Word 未验证。
- 不同 WPS 版本对 `FileDialog`、`FileSystem`、任务窗格接口的支持存在差异，极旧版本可能无法使用。
- 模板使用的字体必须已安装，否则可能出现排版偏差。
- 批量生成会逐份打开/保存 Word 文档，耗时与文件数量、模板复杂度和 WPS 当前状态有关；建议先用「预览第一份」确认。
- 插件不修改模板本身，所有输出均写入所选输出目录。

## 开发说明

- 代码使用 ES5 风格编写，便于在 WPS 的 JS 引擎中运行。
- 新增字段时，在 `modules/fieldRegistry.js` 中补充字段定义与别名，并同步模板识别逻辑。
- 修改生成规则后，请运行 `npm test` 确认回归用例通过。
